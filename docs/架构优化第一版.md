# 架构优化第一版

2026-11-13。基于架构评审实施的第一轮增量改造，目标运行时为 Fastify + PostgreSQL。接口路径和 `{ success, code, message, data }` 响应信封继续保留。

## 已迁移的链路

| 接口 | 新行为 |
|---|---|
| `POST /admin/jobs/:id/review` | 要求 `pass: boolean` 和 `expectedVersion: integer`；驳回必须提供非空 reason；仅待审核且版本匹配的记录允许审核；通过前校验有效期；保存审核历史与审计 |
| `POST /jobs/apply/:id` | 在事务中复核身份、手机号、岗位有效期和重复报名；禁止报名自己的岗位 |
| `POST /jobs/applicants/accept/:jobId/:appId` | 校验归属、待处理状态和岗位有效期；重复相同决定返回原状态，不重复发通知 |
| `POST /jobs/applicants/reject/:jobId/:appId` | 校验归属和状态，避免覆盖其他已完成决定 |
| `POST /jobs/applications/cancel/:jobId/:appId` | 只允许报名者取消待处理报名，重复取消不重复减计数 |
| `POST /insurances/purchase/:id` | 幂等回执、余额扣减、购买快照与流水同事务提交 |
| `POST /jobs/top/:id`、`POST /jobs/refresh/:id` | 幂等收费；校验归属、有效期和服务端费用规则 |
| `GET /admin/finance` | PostgreSQL 全量 SUM/COUNT/GROUP BY；统计和分页来自同一只读快照；按资产类型区分积分与元 |

## 代码边界

```text
contracts/
  architecture-v1.json          运行时请求 Schema
  commands.generated.d.ts       由 Schema 生成的命令类型
  architecture-v1.d.ts          查询结果和共享 DTO
server/
  interfaces/architecture.cjs   HTTP 注册、严格参数校验、身份与响应转换
  application/                 事务、身份复核、幂等回执、领域错误和实例化加密依赖
  modules/recruitment/          审核、报名、报名决定、岗位推广用例与状态规则
  modules/wallet/               购买保险、条件扣费、流水和公开积分扣费接口
  modules/finance/              全量聚合查询
  db/002_architecture_v1.sql    追加迁移
```

新用例显式接收 pool、身份和依赖，不使用全局 `L.db()`，不改写 `process.env`。招聘模块通过钱包公开接口取得费用和执行积分扣款，不自行更新余额或记流水。旧路径仍由兼容层服务，因此本次不是全仓去全局状态或全仓 TypeScript 迁移。

新模块采用 CommonJS + JSDoc，使用独立 strict TypeScript 配置检查；后台审核与财务页使用 TypeScript 和共享 DTO。保持 Node.js 22 运行方式，不增加启动时转译要求。

## 幂等协议

三个付费入口要求请求体包含 `idempotencyKey`，值为 16–128 位字母、数字、下划线或短横线。当前入口不接受其他购买参数。命令唯一范围为当前用户 + 操作 + 幂等键；资源 ID 参与请求指纹。

- 同一键、同一资源：返回首次成功结果，不再扣款或创建新记录。
- 同一键、不同资源：返回 `409 IDEMPOTENCY_CONFLICT`。
- 业务失败：扣款、记录与回执一起回滚。
- 成功后响应丢失：回执已提交，重试读取原结果。
- 回执不自动过期，防止迟到重试被识别成新的扣费。未来若归档，必须继续保留去重能力。

小程序/H5 在本地按用户 ID 和操作路径保存未确定结果的键，同时合并正在进行的相同请求。网络异常、408、429 或服务器异常保留键；收到成功或明确的客户端失败后清理。清除本地存储会丢失未完成意图，服务端仍只能根据客户端提交的同一键识别重试；跨设备重试需要未来增加可查询的操作单。

这不替代微信充值回调已有的订单幂等。本轮未重构充值下单、联系解锁及其他收费入口。

## 审核版本与迁移

追加迁移新增 `jobs.version`、`job_reviews`、`command_receipts`。岗位版本通过数据库触发器递增，旧编辑/状态入口也会更新版本；浏览量、报名数和推广时间变动不单独使内容审核版本失效。

后台岗位列表返回 version，审核按钮提交用户实际看到的版本。遇到 409，页面提示并刷新数据，不自动重试审批。已有审计记录继续保留，新审核写入版本、决定、原因和 requestId。

部署步骤：

1. 备份开发/生产数据库后，发布包含新模块、contracts 与追加 SQL 的后端版本。
2. 在 server 目录执行 `npm ci`、`npm run migrate`；服务启动也会校验并执行编号迁移。不能改写已应用的 `001_initial.sql` 或 `002_architecture_v1.sql`。
3. 配套发布新后台和小程序。旧后台缺少 expectedVersion、旧小程序缺少 idempotencyKey 时，新入口会明确拒绝请求；需要安排客户端升级窗口。
4. 生产小程序配置 `VITE_API_BASE` 指向 PostgreSQL API；云函数直连和内存演示入口仍使用旧实现，不具备本版全部保证。
5. Docker 构建已增加 contracts 目录。使用仓库根目录作为构建 context。

迁移是追加式，回退旧应用时可以暂时保留新表和版本列；不要删除已有回执后重新启用付费入口。

## 事务与并发边界

新写用例仍获取与旧兼容层相同的 advisory transaction lock，并使用条件扣款、岗位行锁、版本条件和唯一约束。统一锁常量位于 `server/db/transaction-lock.cjs`。

财务查询使用 `REPEATABLE READ READ ONLY`，脱离全局写锁。其他旧 GET 可能含状态更新，本轮不擅自移出其原有事务。

由于本轮未获准运行并发测试，没有全面移除写锁，也不宣称吞吐量已经提升到某个指标。后续应逐领域验证不变量后，再替换全局写锁。

## 契约与静态检查

运行时 Schema 位于 `contracts/architecture-v1.json`，新接口使用不做类型强转、不移除未知字段的 AJV 校验。字符串 `"false"` 不会被当作布尔审核决定。错误响应新增稳定 `errorCode` 和 requestId，后台请求层保留它们。

```bash
cd server
npm run contracts   # 从 Schema 重新生成共享命令类型
npm run typecheck   # 新应用模块 strict 静态类型检查
npm run migrate    # 应用编号迁移
```

修改命令 Schema 后需要同时提交生成的声明文件。结果 DTO 当前为手写共享类型，本轮没有建立完整 OpenAPI 客户端生成或全路由响应校验。
